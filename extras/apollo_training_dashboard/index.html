本次日志健康摘要

    训练时如何判读

    • 总 loss 与关键子损失总体下降，且没有 NaN/inf：训练链路通常正常。
    • data_time 长期明显大于 time：优先检查磁盘、CPU 或 DataLoader worker。
    • HBM 轻微波动正常；持续单调增长直至 OOM 才怀疑泄漏。
    • loss 不能替代精度：每个 epoch 的 checkpoint 仍需用 val 集看 mAP 与 mIoU。

    字段与评估指标说明

    训练日志字段用于诊断过程；验证集指标用于判断模型质量。

    1. 先看训练是否稳定loss 是否下降、grad_norm 是否有限、HBM 是否平稳。
    2. 再看验证是否进步以 mIoU 与 mAP 的逐 epoch 趋势为准，不以 train loss 代替精度。
    3. 最后定位弱项结合 Precision/Recall、mATE/mAOE 判断是误报、漏检、定位还是朝向问题。
    越低越好loss（总训练损失）

    loss 是检测、Occupancy 等多个目标按配置加权后的优化目标。它适合判断训练是否收敛，但不能与 mAP/mIoU 直接换算，也不能跨不同配置比较绝对值。健康形态是总体下行、允许 batch 级锯齿；持续上升、突然尖峰或 NaN 才需要排查。

    越低越好loss_cls / loss_bbox

    loss_cls 衡量目标类别判断的错误；loss_bbox 衡量 3D 框中心、尺寸、朝向等回归误差。前者长期不降，优先关注类别不均衡、标注/类别映射；后者不降，关注坐标系、标注质量、图像几何与检测头。二者只能分别看趋势，数值大小不代表谁“更重要”。

    越低越好loss_occupancy / loss_sem_scal

    loss_occupancy 监督每个体素的 Occupancy 语义类别；loss_sem_scal 约束语义尺度/类别结构，缓解稀疏类别学习困难。它们下降只说明训练目标拟合变好；验证集的 mIoU 才是 Occupancy 分支是否真正泛化的主结论。

    过程量lr / grad_norm

    lr 是当前步长。本配置会经历 warmup 后按策略变化，曲线形状应与配置一致。grad_norm 是全模型梯度总体大小；数值有波动正常，但连续增长、突然极大、NaN/inf 往往意味着梯度不稳定。它没有通用“越小越好”的阈值，关键是有限、连续且稳定。

    性能量time / data_time / memory

    time 是一个 iteration 的耗时，反映端到端训练吞吐；data_time 是取数与预处理等待时间，若长期接近或超过 time，通常是磁盘、CPU、解码或 worker 瓶颈；memory 是记录到的 HBM/显存 MB。启动阶段波动正常，稳定期的持续爬升才提示内存泄漏风险。

    越高越好mIoU（Occupancy 主指标）

    mIoU 对每个 Occupancy 语义类别计算预测与真值的交并比，再平均；它既惩罚漏占据也惩罚错占据。它是最应优先汇报的 Occupancy 指标。Apollo README 的同路线参考值为 21.87%；只有数据、配置与评估口径一致时才可严格横比。

    越高越好IoU / Precision / Recall

    IoU 是占据/非占据二分类交并比；Precision=预测为占据的位置中有多少正确，低说明误报较多；Recall=真值占据的位置中有多少被找到，低说明漏检较多。Precision 高而 Recall 低是“保守”；Recall 高而 Precision 低是“激进”。二者需一起读。

    越高越好mAP / NDS（3D 检测主分）

    mAP 是各类别 3D 检测平均精度的均值，衡量分类置信度与空间匹配；是检测的第一主指标。NDS 是 nuScenes 综合分，将 mAP 和多种误差汇总，适合总体比较。Apollo README 的参考 mAP 是 31.94%。本 DLA 配置不预测速度，NDS 受 mAVE 影响，不能与预测速度的模型直接横向排名。

    越低越好mATE / mASE / mAOE / mAVE / mAAE

    mATE：框中心平移误差（米）；mASE：尺度误差；mAOE：朝向误差（弧度）；mAVE：速度误差（m/s）；mAAE：属性误差。它们用于解释 mAP/NDS 的短板。当前 DLA 路线不输出速度，mAVE 偏高或缺失是模型定义所致，不宜单独作为适配失败的证据；某些类别的 NaN 是“该指标不适用”，不是日志损坏。
